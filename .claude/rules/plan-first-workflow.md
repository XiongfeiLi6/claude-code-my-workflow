# Plan-First Workflow

For any non-trivial task, enter plan mode before editing files.

## Protocol

1. Enter plan mode.
2. Read relevant `MEMORY.md` [LEARN] entries.
3. If scope is ambiguous or high-impact, create a requirements spec.
4. Draft implementation plan with file list, order, and verification strategy.
5. Save plan to `quality_reports/plans/YYYY-MM-DD_short-description.md`.
6. Present plan and wait for approval.
7. Exit plan mode only after approval.
8. Start contractor-mode execution.

## Requirements Spec Trigger

Create a spec when any apply:
- Multiple valid interpretations exist.
- Recommendation framing may change outcome.
- Task touches 3+ files or requires 1+ hour.

Spec location:
`quality_reports/specs/YYYY-MM-DD_description.md`

Spec format:
- MUST/SHOULD/MAY requirements
- clarity status: CLEAR / ASSUMED / BLOCKED

## Milestone Check-ins (Early Sessions)

During first sessions, provide updates at:
- spec complete
- plan complete
- first draft complete
- verification complete
- final artifact complete

## Context Survival

Before compaction, ensure:
1. active plan saved
2. session log current
3. key decisions reflected in MEMORY or log
4. open questions listed
